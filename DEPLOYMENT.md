# Lenta CV — Price Tag Recognition: Инструкция по развертыванию

## Архитектура системы

Репозиторий содержит кроссплатформенный конвейер для автоматического распознавания ценников и верификации данных по видеопотоку. Система распределена на два изолированных микросервиса:

| Компонент | Стек | Назначение |
|-----------|------|-----------|
| **API Server** | FastAPI, YOLO-трекер | Приём видеопотока, трекинг объектов, бизнес-логика валидации, фоновые задачи |
| **LLM Server** | llama-cpp-python | Локальный инференс мультимодальной сети Qwen-VL |

### Динамическое определение адреса LLM-сервера

Для обеспечения идентичной работы конвейера как в среде локальной разработки (Native OS), так и в изолированной среде оркестрации (Docker Compose), адрес сервера моделей определяется на этапе инициализации в файле `vision/vision_main.py` через приоритетное чтение переменных окружения:

```python
import os
LLM_BASE_URL = os.getenv("LLM_BASE_URL") or config_dict.get("llm_base_url", "http://localhost:8000/v1")
```

## Вариант 1: Локальный запуск (запуск в одну команду)

Для локальной разработки и отладки все компоненты системы запускаются параллельно с помощью единого Bash-скрипта.

### Подготовка

1. Разместите бинарный файл модели `ZwZ-8B-Q6_K.gguf` в директории `vision/cpp_llm/bin/`.
2. Убедитесь, что в файле `config.yaml` параметр `llm_base_url` равен `http://localhost:8000/v1`.

### Запуск

Из корневой директории проекта выполните:

```bash
./start_all.sh
```

Скрипт автоматически:
- запустит LLM-сервер в фоновом режиме с перенаправлением логов в файл `llm_server.log`;
- поднимет API-сервер на порту `8080`;
- корректно завершит оба процесса при нажатии `Ctrl+C`.

Swagger UI доступен по адресу: **http://localhost:8080/docs**

## Вариант 2: Запуск в Docker-контейнерах (продакшн, CPU)

Рекомендуемый способ развертывания на целевом сервере для изолированной работы микросервисов во внутренней сети Docker.

### Шаг 1: Установка Docker (Ubuntu)

```bash
curl -fsSL https://get.docker.com -o get-docker.sh && sh get-docker.sh
```

### Шаг 2: Конфигурация для Docker

В серверной версии `config.yaml` адрес хоста заменяется на имя внутреннего DNS-сервиса Docker:

```yaml
llm_base_url: "http://llm_server:8000/v1"
```

### Шаг 3: Сборка образов и запуск оркестрации

Из корневой директории проекта:

```bash
docker compose up --build -d
```

### Шаг 4: Мониторинг и логирование

```bash
# Проверка статуса контейнеров (api_server и llm_server должны быть UP)
docker compose ps

# Мониторинг прогрева весов LLM (занимает до 3 минут)
docker compose logs -f llm_server

# Анализ работы YOLO-трекера в реальном времени
docker compose logs -f api_server
```

## Вариант 3: Запуск с поддержкой GPU (NVIDIA CUDA)

Для существенного ускорения инференса мультимодальной модели Qwen-VL — с **~60 секунд** до **2–5 секунд** на кадр — систему можно развернуть с использованием аппаратного ускорения CUDA.

### Шаг 1: Подготовка хост-системы

На сервере должны быть установлены драйверы NVIDIA и пакет **NVIDIA Container Toolkit**, позволяющий Docker-контейнерам использовать ресурсы видеокарты. Проверить доступность GPU:

```bash
nvidia-smi
```

### Шаг 2: Изменение Dockerfile для `llm_server`

Для работы с CUDA образ сервера моделей должен быть собран с компиляцией под соответствующую архитектуру. В `Dockerfile` перед установкой `llama-cpp-python` добавьте флаги компиляции:

```dockerfile
ENV GGML_CUDA=on
RUN pip install llama-cpp-python[server] \
    --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cu121
```

> **Примечание:** Параметр `cu121` выбирается в соответствии с версией CUDA на целевом сервере (например, `cu118` для CUDA 11.8, `cu124` для CUDA 12.4).

### Шаг 3: Настройка `docker-compose.yml`

Контейнеру `llm_server` необходимо делегировать доступ к GPU. Добавьте блок `deploy` в секцию сервиса:

```yaml
services:
  llm_server:
    image: ghcr.io/abetlen/llama-cpp-python:latest-cuda
    container_name: llm_server
    volumes:
      - ./models:/app/models
    ports:
      - "8000:8000"
    environment:
      - MODEL=/app/models/ZwZ-8B-Q6_K.gguf
      - HOST=0.0.0.0
      - PORT=8000
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]
```

### Шаг 4: Запуск и проверка

```bash
docker compose up --build -d
```

После старта команда `docker compose logs -f llm_server` покажет процесс переноса вычислительных слоёв нейросети в видеопамять (VRAM). Полная загрузка модели занимает до **1–2 минут**.

## Спецификация работы при ограниченных ресурсах

### Режим последовательной обработки (BackgroundTasks)

В целях предотвращения аппаратных сбоев из-за нехватки оперативной памяти (минимальные системные требования — **16 ГБ RAM**) планировщик FastAPI обрабатывает входящие видеопотоки строго последовательно. При одновременной отправке нескольких файлов запросы асинхронно кэшируются в очередь фонового воркера без блокировки основного потока API.

### Оптимизация RAM (предупреждение `failed to mlock`)

При запуске контейнера на CPU-архитектуре без поддержки жёсткой фиксации страниц памяти (`mlock`) операционная система может задействовать виртуальную память (файл подкачки). Данное поведение является **штатным** и не препятствует корректному завершению OCR-анализа. Среднее время обработки одного информативного кадра — около **60 секунд**.

### Валидация итоговой отчётности

В процессе анализа видеопотока выполняется строгая фильтрация артефактов движения и расфокусировки. Объект заносится в финальный отчёт только при успешном прохождении пороговых метрик детекции текста.

> ⚠️ До завершения полной обработки видеофайла эндпоинт скачивания возвращает статус **`400 Bad Request`**.

### Автоматический сбор мусора

По завершении жизненного цикла фоновой задачи (или при возникновении критического исключения в процессе декодирования видео) система автоматически вызывает деструктор временных файлов для оптимизации дискового пространства. Готовые аналитические отчёты сохраняются в директории `_output/`.
