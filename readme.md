# 🛒 Lenta CV Pipeline: Распознавание ценников

Асинхронный конвейер для детекции, трекинга и мультимодального распознавания ценников из видеопотока. Система построена на базе микросервисной архитектуры с использованием локальных LLM и мажоритарного голосования для защиты от галлюцинаций OCR.

## ⚙️ Общая логика работы пайплайна (более подробные описания в соответствующих папках)

Система представляет собой конвейер из независимых слоев. Главная парадигма — **мажоритарное голосование кадров**: мы не доверяем нейросети распознавание по одной картинке, а накапливаем историю для каждого физического объекта в кадре.
### 0. Обучение модели (Model train)
* Используем для автоматической разметки  `grounding_dino`
* Дообучаем модель  `yolo12` для обнаружения ценников
* Визуализируем для проверки
Этот модуль не необходим для работы приложения. Только для подготовки моделей

### 1. Захват и нарезка (Detection & Tracking)
* **Чтение потока:** `video_gen_tracker` открывает видеофайл. Для экономии ресурсов кадры пропускаются аппаратно (`cap.grab()`), а декодируются только нужные (согласно параметру `skip_frames`).
* **Детекция и Трекинг:** YOLO находит ценники, а ByteTrack присваивает каждому уникальный ID.
* **Адаптация:** `detector_adapter` берет сырые координаты, вырезает ценник (с защитными отступами) и, при необходимости, поворачивает его. На выходе формируется унифицированный DTO `TrackedCrop`.

### 2. Предобработка и Анализ (Vision Pipeline)
Каждый полученный кроп проходит через систему фильтров внутри `vision_main.py`:
* **Blur Check:** Сильно смазанные кадры отбрасываются (экономим время VLM).
* **Color Check:** Анализ цветовой гистограммы в HSV для определения типа ценника (акция, обычный).
* **Upscale:** Кроп пропускается через сверхразрешение (EDSR x3) для повышения читаемости мелкого шрифта.
* **Barcode/QR:** Классические алгоритмы (`wechat_qr`, `pyzbar`) извлекают штрихкоды до нейросети.
* **VLM Inference:** Улучшенное изображение отправляется на локальный сервер (`llama-cpp-python`). Квантованные GGUF-модели анализируют кроп и возвращают строгий JSON.

### 3. Оркестрация и Голосование (Controller)
* **Накопление (State Manager):** Оркестратор сохраняет успешные JSON-ответы в память конкретного `track_id`.
* **Валидация:** Ответы без ключевых полей (цена, название) помечаются как бракованные.
* **Голосование (Results Aggregator):** Когда ценник накопил `track_success_threshold` успешных кадров (или исчез по таймауту), трек закрывается. Агрегатор сравнивает ответы с разных кадров и выбирает самое частое значение (мажоритарное голосование).
* **Оценка уверенности:** При совпадении данных трек получает статус `good`, при конфликте — `uncertain`.

### 4. Финализация (Main)
После завершения обработки видеопотока, скрипт `main.py` форматирует данные агрегатора, добавляет метаданные (координаты, таймстемпы) и выгружает итоговую матрицу в строгий `submission.csv`.
