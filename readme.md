⚙️ Общая логика работы пайплайна
Система представляет собой асинхронный конвейер из трех независимых слоев. Главная парадигма — мажоритарное голосование кадров: мы не доверяем нейросети распознавание по одной картинке, а накапливаем историю для каждого физического объекта.

Этап 1: Захват и нарезка (Detection & Tracking)
Чтение потока: video_gen_tracker открывает видеофайл. Для экономии ресурсов тяжелые 4K-кадры пропускаются аппаратно (cap.grab()), а декодируются только нужные (согласно параметру skip_frames).

Детекция и Трекинг: YOLO находит ценники, а ByteTrack присваивает каждому уникальный ID.

Адаптация: detector_adapter берет сырые координаты, вырезает ценник (с защитными отступами) и, при необходимости, поворачивает его. На выходе формируется унифицированный DTO TrackedCrop, который передается дальше.

Этап 2: Предобработка и Анализ (Vision Pipeline)
Каждый полученный кроп проходит через жесткую систему фильтров внутри vision_main.py:

Blur Check: Если кадр сильно смазан в движении — он отбрасывается (экономим время LLM).

Color Check: Анализ цветовой гистограммы в HSV для определения типа ценника (акция, обычный, карта).

Upscale: Кроп пропускается через сверхразрешение (EDSR x3), чтобы мелкий шрифт стал читаемым.

Barcode/QR: Параллельно работают классические алгоритмы компьютерного зрения (wechat_qr, pyzbar), пытаясь вытащить штрихкоды до нейросети.

VLM Inference: Улучшенное изображение кодируется в Base64 и отправляется через llama_cpp_client на локальный сервер (через llama-cpp-python). Использование квантованных GGUF-моделей позволяет держать весь контекст в ограниченной VRAM, гарантируя строгий JSON на выходе.

Этап 3: Оркестрация и Голосование (Controller)
Накопление (State Manager): Оркестратор сохраняет успешные JSON-ответы от LLM в память конкретного track_id.

Валидация: Если LLM вернула мусор (отсутствует цена или название), кадр помечается как бракованный и не идет в зачет.

Голосование (Results Aggregator): Как только ценник накопил track_success_threshold успешных кадров (или исчез из видео по таймауту), трек закрывается. Агрегатор покомпонентно сравнивает все ответы (например, цены с 3-х разных кадров) и выбирает самое частое значение.

Оценка уверенности: Формируется Confidence Score. Если на разных кадрах результаты совпали — статус good. Если был конфликт галлюцинаций — uncertain.

Этап 4: Финализация (Main)
После завершения видеопотока, Оркестратор отдает агрегированные данные. Скрипт main.py форматирует их, подмешивает недостающие колонки и выгружает в строгий submission.csv согласно требованиям хакатона.
